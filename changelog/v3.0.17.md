# EzSDR v3.0.17

## Summary

* 新しいdeviceである`UHD_RFNoC`を追加


## UHD_RFNoCの追加

### 概要と設定例

UHD/USRPのRFNoCの機能を利用するために，新しいデバイス`UHD_RFNoC`を追加しました．
たとえばUSRP X300で，送信と受信を2系統ずつ設定し，また，`RF A`ではRFNoCのReplayブロックを用いてループして送信をし続けるような設定は以下のように記述できます．

```json
"devices": {
    "USRP0": {
        "type": "UHD_RFNoC",
        "args": "addr0=192.168.10.2",
        "timeref": ["internal"],
        "clockref": ["internal"],
        "connections": [
            "0/Replay#0:0 => 0/Radio#0:0"
        ],
        "radios": [
            {
                "for": ["0/Radio#0:0", "0/Radio#1:0"],
                "tx-args": "",
                "tx-rate": 10e6,
                "tx-freq": 2.4e9,
                "tx-gain": 10,
                "tx-ant": "TX/RX",
                "tx-bw": 10e6,
                "rx-args": "",
                "rx-rate": 10e6,
                "rx-freq": 2.4e9,
                "rx-gain": 10,
                "rx-ant": "RX2",
                "rx-bw": 10e6
            }
        ],
        "tx-streamers": [
            { "type": "replay", "connect_to": ["0/Replay#0:0"] },
            { "type": "default", "connect_to": ["0/Radio#1:0"] }
        ],
        "rx-streamers": [
            { "type": "default", "connect_from": ["0/Radio#0:0"] },
            { "type": "default", "connect_from": ["0/Radio#1:0"] }
        ]
    }
},
```

上記設定の詳細は次の通りです．

* `"connections"`: RFNoCブロックの接続の設定です．`<デバイス番号>/<上流ブロック名>:<上流ポート番号> => <デバイス番号>/<下流ブロック名>:<下流ポート番号>`というフォーマットで指定します．今回の設定`"0/Replay#0:0 => 0/Radio#0:0"`は，0番目のデバイスの`Replay#0`というブロックの0番ポートの出力を，0番目のデバイスの`Radio#1`というブロックの0番ポートの入力に接続する，という意味です．
* `"radios"`: `Radio`ブロックの設定をします．`"for"`で設定対象のブロック及びポートを指定できます．今回は，二つのブロック`"0/Radio#0:0", "0/Radio#1:0"`に対して同じ設定を適用しています．USRP X300であれば`"0/Radio#0:0"`が`RF A`ポート，`"0/Radio#1:0"`が`RF B`ポートに対応します．送信の設定と受信の設定は別れており，不要であれば片方の設定を書かないことも可能です．
* `"tx-streamers"`: 送信ストリーマーの設定です．`type`はReplayブロックを使用したループ送信の場合は`"replay"`を指定して，そうでない普通の送信の場合は`"default"`を指定します．また，`"connect_to"`はストリーマーの接続先のRFNoCブロックで，`"replay"`であればReplayブロックに接続している必要があります．`"replay"`は，設定した信号をFPGAでループして送信を続けるものであり，一度信号を設定してしまうとその後はPCとUSRPの間で通信なしでループ送信が実現されます．ネットワークの帯域や遅延の問題がある場合に`"replay"`は有効です．
* `"rx-streamers"`: 基本は`tx-streamers`と同じですが，`"replay"`は指定できません．

この設定では，次のように信号が流れていきます．

* 送信ストリーマー0の信号の流れ：PC（クライアントプログラム → EzSDRサーバー → UHD） → USRP（Replayブロック"0/Replay#0:0" → Radioブロック"0/Radio#0:0"）→ USRP出力ポートA
* 送信ストリーマー1の信号の流れ：PC（クライアントプログラム → EzSDRサーバー → UHD） → USRP（Radioブロック"0/Radio#0:0"）→ USRP出力ポートB
* 受信ストリーマー0の信号の流れ：USRP入力ポートA → USRP（Radioブロック"0/Radio#0:0"） → PC（UHD → EzSDRサーバー → クライアントプログラム）
* 受信ストリーマー1の信号の流れ：USRP入力ポートB → USRP（Radioブロック"0/Radio#1:0"） → PC（UHD → EzSDRサーバー → クライアントプログラム）

送信ストリーマー1では，USRPから信号を送信し続けるためには，PCから絶えずUSRPに信号データを供給し続ける必要があり，これが高サンプリングレートで不安定な原因になります．
一方で，Replayブロックを用いる送信ストリーマー0では，PCから一度送信信号を設定してしまうと，その後はPCとUSRP間の通信がなくてもUSRP内部にあるReplayブロックがループ送信をし続けてくれます．


### `MultiUSRP`の設定からの変換

`MultiUSRP`デバイス設定から`UHD_RFNoC`デバイス設定への変換方法を以下に示します．

* `type`: `MultiUSRP` -> `UHD_RFNoC`
* `args`, `timeref`, `clockref`: そのまま同じものを指定してください
* `mode`: `MultiUSRP`で設定していた`mode`は`UHD_RFNoC`では不要です
* `tx-subdev`: `MultiUSRP`で設定していた`tx-subdev`は`UHD_RFNoC`では不要ですが，USRP X300での`A:0`は`UHD_RFNoC`では`<デバイス番号>/Radio#0:0`で，`B:0`は`<デバイス番号>/Radio#1:0`のことだと思ってください．デバイス番号は`args`に指定した`addr0`とか`addr1`の末尾の番号のことです．
* `rx-subdev`: `MultiUSRP`で設定していた`rx-subdev`は`UHD_RFNoC`では不要ですが，USRP X300での`A:0`は`UHD_RFNoC`では`<デバイス番号>/Radio#0:0`で，`B:0`は`<デバイス番号>/Radio#1:0`のことだと思ってください．デバイス番号は`args`に指定した`addr0`とか`addr1`の末尾の番号のことです．
* `tx-channels`: `MultiUSRP`で設定していた`tx-channels`は`UHD_RFNoC`では不要です．
* `rx-channels`: `MultiUSRP`で設定していた`rx-channels`は`UHD_RFNoC`では不要です．
* `radios`: `UHD_RFNoC`で送受信のサンプリングレートや周波数を設定する項目で，`MultiUSRP`で設定していた`tx-channels`や`rx-channels`に相当します．`MultiUSRP`の`tx-channels`や`rx-channels`では，送受信の設定が別れており，それぞれでチャネル番号ごとに設定を書いていました．`UHD_RFNoC`の`radios`設定では，Radioブロックに対して設定を記述します．つまり，`MultiUSRP`での`A:0`に設定したいのであれば`radios`では`"for": ["<デバイス番号>/Radio#0:0"]`と指定し，`B:0`に設定したいのであれば`radios`では`"for": ["<デバイス番号>/Radio#1:0"]`と指定します．
* `tx-streamers`: `MultiUSRP`では接続先のチャネル番号を指定していましたが，`UHD_RFNoC`では接続先のRFNoCブロックを指定します．`type`は`"default"`で`connect_to`が`"<デバイス番号>/Radio#<0か1>:0"`が`MultiUSRP`と全く同じ動作をします．もし信号のループ送信しかしないのであれば`"replay"`も使用してみてください．`"replay"`を使用する場合には`connect_to`を`"<デバイス番号>/Replay#0:<0か1>"`に設定して，`"connections"`でRadioブロックとReplayブロックを接続してください．
* `rx-streamers`: `tx-streamers`と同じですが，`replay`に未対応です．
* `connections`: `UHD_RFNoC`固有の設定で，USRP内部のFPGAのRFNoCブロックの接続設定をします．特に，`tx-streamers`で`replay`を使用する場合は，`"<デバイス番号>/Replay#0:<0か1>"`を`"<デバイス番号>/Radio#<0か1>:0"`に接続する必要があり，例えば`connections: ["0/Replay#0:1 => 0/Radio#1:0"]`のように記述します．
